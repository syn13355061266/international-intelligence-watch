## 上游对照与运行节奏

对照 [AIHOT 的固定版本 c535666](https://github.com/KKKKhazix/AIHOT/tree/c535666f35e78e55beb0bc9de80bb0032e45cf68)，核对 worker 调度、采集队列、分析、提取、翻译与请求回执。没有把上游新的产品模块整体并入本站。

| 环节 | 原本机设置 | 本次本机设置 |
| --- | --- | --- |
| 来源调度 | 曾限制来源和每日模式 | 每分钟检查到期来源，每轮最多 40 个 |
| 来源采集 | 并发 4，每次额外等待 2 秒 | 上游默认并发 8，取消额外等待 |
| 正文提取 | 并发 3 | 上游默认并发 4 |
| 资料分析 | 并发 3 | 上游默认并发 6 |
| 订阅模型额外闸门 | 最多 2 个请求，间隔 5 秒 | 最多 12 个请求，无额外固定间隔；429 时暂停新请求 |
| 全文翻译 | 每轮 2 篇 | 每 5 分钟启动，最多 30 篇，两篇并行 |
| 漏单补排 | 每 5 分钟 | 每 5 分钟，返回实际补排数量 |

这是滚动轮询，来源到期后采集，采集后立即排入正文提取和分析队列；不是订阅推送，也不是统一等几小时才处理。免费新闻来源沿用各自间隔和上游自适应规则，活跃来源约 15 分钟、普通来源约 60 分钟。四外新入口初始为每 60 分钟。付费采集器仍需对应配置，本机未开启 Jina、SocialData 或飞书推送。

分析保持：宽召回预筛 → 两次独立评分 → 中文写作 → 发布 → 事件归组。结构化与评分并行；两次评分依次运行。没有正文、摘录或帖子材料时不发送付费预筛、评分和写作请求。历史资料进入低优先级归组以正常结案，不制造新事件热度；旧 cron 队列连同遗留任务一起退役。

本机适配：保留新消息优先的排队规则，避免约 3.8 万条旧积压挡住新消息；保留回执复用、失败退避、停机保护和预算熔断。订阅连接默认使用 low 推理，避免所有编辑步骤都承担较长推理延迟；可用 `MODEL_REASONING_LEVEL` 调整。每分钟/小时/日请求上限为 100/2000/20000，这是请求次数保护，不代表服务商额度或金额预算。

## 中文正文与个人试阅

排查基线：862 条发布记录中，860 条受来源许可限制只展示摘要，译文表只有 1 条。这是主要原因；换成 API Key 不会改变来源许可或自动补出未抓到的正文。

按用户明确选择，开启 `LOCAL_FULLTEXT_PREVIEW=true`：所有已确认抓取正文的编辑来源材料都可进入个人翻译队列，优先精选、合格发布、其他发布、尚未发布材料。订阅实跑已成功产生完整中文正文，无需为这项修复立即购买 API。

- 只在 SITE_URL、Web/API 绑定均为本机回环地址时生效；存在 Railway 环境标记时失效。
- 本机详情、原文与 Markdown 下载允许个人试阅，响应私有且不缓存，页面不索引；Web 拒绝公网 Host。
- 不修改来源的 `site_fulltext`、`syndicate_fulltext`，不改变公开 RSS、开放 API 和 MCP 的许可规则。
- 中文原文不占用外文翻译批次。阿拉伯文、日文等也进入翻译，不再只识别拉丁字母。
- 未声明语言时按汉字占比识别中文，少量中文标签不再让整篇英文被跳过；本机排查发现 1,132 篇此类正文。
- 英文照抄、段数不符、丢失链接或媒体的答案不能成为完整译文；拒收对应回执，允许有上限地重新请求。不完整译文不会被标成完整中文正文。
- 每个修订最多三次文章级尝试；预算、限流、停机和待核对回执不耗掉这些尝试。沿用上游单篇 60,000 字符处理上限；超过上限标记不完整。

完整是程序对段落、结构及语言的校验结果，不代表人工逐字审校。未确认抓取的正文、来源阻拦、付费墙或网络失败仍需在后台处理。
