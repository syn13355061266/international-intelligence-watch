# 正文与采集排查（2026-10-11）

后续本机设置与完整排查见 [2026-10-30 采集、翻译与四外试行](processing-restore-2026-10-30.md)。下文保留为当时记录，不代表目前并发和翻译范围。

## 正文缺失的原因

本机排查时有 485 个信源、208 条发布记录。所有信源的 `site_fulltext` 都关闭，发布记录的 `body_mode` 全为 `summary`，译文表为空。实际已有部分文章完整原文，但发布层不将其送到页面。原版 AIHOT 也使用这道开关，并非用 API Key 就自动获得全文。

此外，原来的翻译任务只处理最近三天的精选；纯文本没有 HTML 的完整内容也不能在新闻详情页显示。原文尚未翻译时被误标为不完整。此前增加的 RSS 摘录没有解决这些问题。

本次修改：

- 已确认完整的纯文本也可显示和导出；原文与译文分别展示，沿用 AIHOT 的导读、正文、语言切换、目录、来源和右侧推荐布局。
- `TRANSLATE_SCOPE=published` 将翻译范围扩展到可进入公开内容池、具有全文许可的文章，包含较早的待译文章。默认配置仍保留原有精选模式。
- 没有译文先展示完整原文；没有可展示正文时说明原因并提供原文链接。摘录不冒充全文，撤销许可也不会通过译文泄露全文。
- `industry/fulltext-permissions.json` 记录已核查的官方来源和条件；`node --env-file=.env scripts/enable-reviewed-fulltext.ts` 审计启用并排队重新发布。新建站点先正常 seed，再执行。种子默认仍不开放全文。
- 新增 GOV.UK 外交部公告 Atom。英国政府正文注明 OGL v3.0；欧盟理事会注明来源与版权；中文标识为非官方 AI 翻译。第三方受限材料、媒体付费墙不在开放范围。

## 为什么部分栏目一直缺少数据

模型预筛仍要求内容与旧四专题有关，导致外交、军事等十领域内容被误排除。已同步用户批准的十栏目，并用 `scripts/repair-intelligence-backlog.ts --apply` 将旧规则排除的 117 条资料分批交给 worker 重评；脚本本身不调用模型。已经使用新规则处理的资料不会反复重置。

## 采集修复与当前运行设置

原 `.env` 只允许 20 个指定信源，并排除了 `web_list`，Telegram 根本没有进入调度。每日任务只取前 40 个来源一次，没有持续清空当天待抓列表。另有未配置 Jina 却尝试调用付费回退的错误。

当前本地设置：

```dotenv
COLLECT_ENABLED=true
MODEL_CALLS_ENABLED=true
COLLECT_SCHEDULE=rolling
COLLECT_KINDS=rss,web_list,json_list
COLLECT_SOURCE_IDS=
COLLECT_SKIP_JINA=true
JINA_BODY_FALLBACK=false
FETCH_SCHEDULE_BATCH=12
FETCH_CONCURRENCY=4
FETCH_SPACING_MS=2000
EXTRACT_CONCURRENCY=3
ANALYZE_CONCURRENCY=3
MODEL_MIN_SPACING_MS=5000
MODEL_MAX_CONCURRENCY=2
TRANSLATE_SCOPE=published
TRANSLATE_BATCH=2
```

现已恢复全天滚动采集：每分钟最多补入 12 个来源任务，待执行队列按两个批次限制。普通免费编辑来源按活跃度每 15–60 分钟再次抓取；4 个采集、3 个正文提取、3 个文章分析任务并发。订阅模型实际最多同时 2 个请求，启动间隔至少 5 秒，429 后共享冷却 60 秒，再由持久化队列退避重试。本站模型预算为每分钟 12 次、每小时 300 次、滚动 24 小时 3000 次；这不是服务商承诺的订阅额度。

正文网络错误和 429/5xx 交给任务重试，不直接判作没有正文。没有 Jina 凭据时只走免费提取。Telegram 修复了某些相册/不支持的媒体消息将日期放在卡片外侧的问题，匹配同一消息链接的时间；无法解析有文字的消息会显示失败原因。

订阅模型仍走原有回执与预算。当前本地安全上限为每分钟 6 次、每小时 120 次、滚动 24 小时 1000 次；这是调用次数保护，不是订阅的实际额度，也不是 API 费用。供应商 429、网络中断、订阅额度耗尽仍可能暂停任务，排队内容不会因此丢弃。一次文章分析有多个模型步骤，因此“1000 次调用”不等于“1000 篇文章”。

## 实际验收与边界

- 官方安理会发言 `jy68w1u7n1bwexj0d81qg3lez`：3136 字符原文已保存，接入的 `openai-codex / gpt-6-sol` 生成中文标题、导读和完整译文；译文表 `complete=true`。
- CISA KEV 与 NASA EONET 公共 JSON 可读取；Telegram `dsns_telegram` 修复后实收 3 条，不再是误报成功的 0 条。
- 本次初始验收已获得多批此前未进入白名单的免费来源，完整轮询仍在进行。当前轮询不会覆盖需要独立凭据且未配置的服务，也不承诺第三方一定响应。
- 多伦多星报等仍可能返回限流或网络错误；部分来源有 403/404。不会把这些伪装成采集成功，也不会用增加并发或重复购买 Jina 来掩盖问题。
- 首次历史回填仍受各来源 `initialBackfillLimit` 限制；日常增量保留正常返回窗口。要做完整历史归档，应单独设置回填范围，避免挤占每天的新消息处理。
- 本地 PostgreSQL 保存原始资料、修订、发布、译文和任务；电脑、数据库、代理与 worker 必须持续运行才能自动更新。GitHub Pages 只能承载静态前端，不能运行这些后台任务。

## 与 AIHOT 的功能对应

保留精选、全部动态、热点榜、日报、主题、收藏、事件关联、正文语言切换、原文链接、Markdown/分享与管理后台。主题和预筛采用国家安全领域。AI 专用模型排行榜和 Codex 重置监控原先已关闭，本次没有将它们冒充情报模块。Logo 保留国际情报观察品牌并恢复图片比例，后台入口使用独立布局空间，避免遮住文章操作。

Codex 聊天窗口出现的 `{"detail":"Bad Request"}` 是另一个客户端请求故障，本次未复现，不能用网站的接口修复来声称解决；当前对话和工具调用已恢复。

## 滚动采集与优先级（2026-10-11）

新文章根据发布时间排序；标题、短摘要中的战略议题线索、来源等级与已知重要性评分可给予最多八小时的排队加分，不改变文章的入选分数或门槛。真正的历史回填排在实时新闻之后；新来源首次导入的近期新闻仍可优先处理。启动与每五分钟安全检查会同步调整已有等待任务，保留正在运行的任务、重试时间及模型回执。

日报继续在北京时间 08:00 汇总前一日 08:00 至当日 08:00 的已发布精选；采集与发布全天进行。该时间是生成任务的触发时间，网络、额度与处理积压可能导致延迟。
