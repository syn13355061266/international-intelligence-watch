# 国际情报观察：主题扩展与持续更新

## 为什么页面没有内容

2026-10-01检查本地预览数据库：480条信源配置，文章、分析、发布情报、日报均为0。配置来源与栏目不会生成新闻；当前只启动网页和API，没有启动采集处理worker，没有项目`.env`，预览的采集和模型开关关闭。因此不是新闻被前端隐藏，而是内容链路尚未开始。

展示链路：来源抓取 → 原始资料 → 相关性判断与中文摘要 → 精选评分及结构化国别/主题标注 → 事件归并 → 统一公开发布层 → 网站/RSS/API → 日报。原始资料或未证实线索不能直接伪装成已审核的情报。热点事件还要求多源支持，单篇文章入库不保证立即出现热点卡片。

## 全天上线与每日自动更新

本机预览只适合检查页面；关机、休眠或停止后台进程会中断更新。长期运行使用常开服务器。将**当前已修改项目**部署到服务器，而不是重新克隆未修改的上游示例。现有`docker-compose.yml`已包含数据库、迁移初始化、API、worker、网页，以及可选Caddy HTTPS。

1. 准备服务器、域名、Docker与Compose。仓库原部署建议至少2核4GB，具体容量取决于启用源量。正式构建前填写部署配置，不能沿用临时预览数据库的免密访问。
2. 从`.env.example`创建服务器`.env`，填写管理员密码、随机会话/图片签名、数据库密码，以及模型服务商的`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`。密钥留在服务器或本地配置，不发到聊天、不上传到公开仓库。站址填写`SITE_URL`，域名填写`SITE_DOMAIN`。
3. 先设置预算并小规模试跑：后台设置中限制模型每分钟、每小时、每天请求数，再逐批启用来源。原有预算是**请求数量上限**，不能直接当作每天人民币费用硬上限；金额还要在模型服务商设置限额并结合token记录观察。480个来源全部首轮采集会造成较大的待处理量，不应在预算未知时直接放开。
4. 正式运行需`COLLECT_ENABLED=true`、`MODEL_CALLS_ENABLED=true`，并让worker保持运行。开发验证仍保持关闭。没有模型凭据或预算已熔断时，不能保证中文动态与日报生成。
5. 域名解析后设置`PORT=127.0.0.1:3000`、`TRUST_PROXY=true`，运行`docker compose --profile https up -d --build`；访问域名HTTPS。没有域名的内网试用可先按`docs/deploy.md`启动。
6. 服务已设置`restart: unless-stopped`；Docker与服务器也要启用开机启动。数据库和上传数据使用持久卷，配置数据库每日备份与离机存储，并验证恢复。
7. 后台“运行”检查worker和定时任务，“信源”检查抓取失败，“模型与评测”检查token与调用结果。查看`docker compose logs --tail 100 worker api web`定位问题。

项目已有北京时间调度：来源每分钟检查是否到期；热点每5分钟计算；日报每天08:00覆盖前一天08:00至当天08:00；周报周一10:00；月报每月1日10:30；每小时15分尝试补齐漏报。日报自动任务不会无条件重写已完成的一期。没有新的入选资料时日报任务报错并等待补齐，**不会生成虚假的空日报**。

首轮回填资料可能被标为历史回填而不进入日报。上线后以真实新到达、已发布的精选资料验证下一期日报，不要只检查历史回填数。

要保证每日更新，关键是来源可达、worker常驻、模型凭据及余额有效、预算未熔断、存在窗口内的精选资料。部署文档：`docs/deploy.md`。通知推送是独立配置，尚未提供接收渠道时不启用。

- 十个主栏目已批准；后续可继续调整覆盖边界。
- 模型服务商、每天费用目标及服务商金额硬上限；在本地配置密钥。
- 长期服务器、域名和部署区域。
- 优先监测国家和第一批来源；目录全覆盖仍需逐步检查各国实际信源覆盖。
- 日报是否保留北京时间08:00，是否需要即时告警与飞书等推送。
- 用100–200条人工标注资料校准精选，并确认上线的运营者、联系邮箱、条款与隐私说明。
